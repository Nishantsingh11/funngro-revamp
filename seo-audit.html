Funngro Website Revamp · SEO audit report

SEO audit of funngro.com

Audited on 7 October 2026. Pages checked: the homepage, /earn (the teen page), /for-brands (the company page), /faq, robots.txt and sitemap.xml.

Summary

funngro.com gets the visible basics right and scores 100 for SEO in Lighthouse. The main risk sits underneath that score. The server sends an almost empty page, and everything a search engine reads (the text, headings, links, meta description and canonical tag) is added afterwards by JavaScript.

Pre-rendering the pages fixes that and several smaller findings at the same time. After that, the biggest gains are a real 404 status for missing pages, one consistent website address, and rewriting the Earn page for the teen audience it is meant for.

Top five fixes, in order

  1. Send the full page content in the server HTML (pre-render or server-side render).
  2. Put the meta description and canonical tag in the server HTML.
  3. Return a real 404 status for pages that do not exist.
  4. Use www.funngro.com everywhere and make the redirect permanent (301).
  5. Rewrite /earn around teens and students, with a cleaner heading structure.

What already works

  • HTTPS with HSTS, and every address variant ends up on one host.
  • A valid robots.txt that blocks admin, auth and API paths and points to the sitemap.
  • A unique, well-sized title on each page, with Open Graph and Twitter tags in the server HTML.
  • Exactly one H1 on each page checked.
  • Alt text on all 19 homepage images, and 18 of them lazy-loaded.
  • Structured data for Organization, WebSite, BreadcrumbList, FAQPage and MobileApplication.
  • Static files are compressed and cached for a year, and fonts are self-hosted.
  • Accessibility and best-practice scores of 100 on all three pages.

Findings

High priority

1. The server sends an empty page

Evidence
Every URL returns about 3.5 KB of HTML whose body is only <div id="root"></div>. The server HTML for /earn has 0 headings, 0 links and 0 words of body copy. The content appears only after a 636 KB JavaScript bundle (192 KB compressed) has run. A request sent as Googlebot gets the same empty page.
Why it matters
Google can run JavaScript, but it does so in a later second pass, which slows down indexing of new and changed pages. Crawlers that do not run JavaScript see no content and no internal links at all.
Fix
Pre-render the marketing pages at build time, or render them on the server, so the full HTML is in the first response. These pages are static content, so pre-rendering is enough.
High priority

2. Meta description and canonical tag are missing from the server HTML

Evidence
The server HTML of /, /earn and /for-brands contains no <meta name="description"> and no <link rel="canonical">. Both are injected later by JavaScript.
Why it matters
These two tags control the search snippet and which URL gets the ranking credit. They should not depend on a script running.
Fix
The server already writes a page-specific title and Open Graph tags into the HTML. Add the description and canonical in the same place.
High priority

3. Missing pages return 200 instead of 404

Evidence
/zzz-not-a-page-123, /company and /teen all return HTTP 200 with the homepage title. JavaScript then swaps in a "Page not found" message and a noindex tag.
Why it matters
This is a soft 404. Any mistyped or outdated link looks like a working page, which wastes crawl budget and shows up as soft-404 errors in Search Console.
Fix
Return a 404 status from the server for any path that is not a known route.
High priority

4. Two different website addresses are in use

Evidence
The canonical tag, og:url and the server-side structured data use https://funngro.com. That address redirects to https://www.funngro.com, which is the one used in the sitemap and robots.txt. The redirect is a temporary 302.
Why it matters
The canonical tag points at a URL that redirects elsewhere, so Google receives mixed signals about the preferred address. A 302 also tells search engines the move is temporary.
Fix
Use https://www.funngro.com in every canonical, og:url and structured-data URL, and change the redirect to a 301.
Medium priority

5. Titles change after JavaScript runs

Evidence
On /earn the server title is "How to Earn Online as a Teen in India | Funngro". After JavaScript it becomes "Earn Money Online Through Online Jobs & Remote Work", with no brand name. The homepage title changes too. Both pages then carry two og:title tags with different values.
Why it matters
Search engines and social previews can pick either version, so the page is described inconsistently.
Fix
Keep one title per page and write it in one place.
Medium priority

6. The Earn page does not speak to teens

Evidence
The server title promises earning "as a Teen", but the words "teen" and "student" appear 0 times in the page copy. The copy repeats generic phrases instead: "earn money" 14 times, "part-time jobs" 13 times and "online work for earning" 4 times, in roughly 1,200 words.
Why it matters
The page competes for broad job-search terms rather than the specific searches Funngro's audience makes, and the repeated phrases read as keyword stuffing.
Fix
Write the page for one search intent, such as earning money online as a teen or student in India, and use natural language.
Medium priority

7. Heading structure on the Earn page is overloaded

Evidence
/earn has 52 headings. "What you need" is used as an H3 four times, including above lists of payout speeds and pay ranges, and single bullet points such as "Zero withdrawal fees" are marked up as H4 headings.
Why it matters
Headings tell search engines and screen readers what each section is about. When list items are headings, that outline loses its meaning.
Fix
Use H2 for sections and H3 for the items inside them, and make list items normal list items.
Medium priority

8. Structured data is duplicated and contradicts itself

Evidence
After rendering, the homepage has three Organization blocks and two WebSite blocks. The server-side Organization gives the legal name "Funngro Innovations Pvt Ltd" while the JavaScript one gives "Wishbanc Technologies Private Limited". The logo field points to the 1200×630 social image, not a logo. The Instagram link in sameAs is instagram.com/fun.n.gro, while the Funngro app links to instagram.com/funngro.
Why it matters
Conflicting company details weaken the brand's knowledge-panel information and make the markup less trustworthy.
Fix
Keep one Organization block with the correct legal name, a real logo file and verified profile links.
Medium priority

9. FAQ answers are not in the page

Evidence
/faq marks up 37 questions in FAQPage structured data, but none of the 37 answers is present in the rendered page until a question is tapped. The page text is only about 390 words.
Why it matters
The answers are the most useful long-tail content on the site, and they cannot be indexed as page content. Google also expects marked-up content to match what is on the page.
Fix
Keep the answers in the HTML and collapse them with native <details> elements.
Medium priority

10. Page speed on mobile is below target

Evidence
Performance scores are 70 to 75. LCP is 3.7 s on /earn and 3.9 s on /for-brands, TBT is 1,250 ms on the homepage, and CLS is 0.11 on /for-brands. Lighthouse estimates 93 to 98 KiB of unused JavaScript per page, and 17 of 19 homepage images have no width and height attributes.
Why it matters
Core Web Vitals are a ranking signal, and most of Funngro's audience is on mobile.
Fix
Pre-rendering (finding 1) brings LCP down. Split the JavaScript by route and add width and height to images.
Medium priority

11. The company page is light on proof

Evidence
/for-brands has about 700 words, no FAQ and no named client. Its results come from one "representative" campaign with the brand name held back under NDA.
Why it matters
Business buyers and search engines both look for evidence. Named case studies and answered questions are what earn trust and long-tail traffic.
Fix
Add an FAQ with FAQPage markup, client logos or named case studies, and link to them from this page.
Low priority

12. Smaller clean-ups

  • /earn says "over 5,000 live campaigns" while /for-brands says "5,000+ brands" and "1,000+ live projects". Make the numbers agree.
  • The site has an English, Hinglish and Hindi switch, but there are no hreflang tags and no Hindi URLs in the sitemap. If the language only changes in the browser, the Hindi content cannot rank.
  • All 39 sitemap URLs share the same lastmod date of 26 June 2026. Use real modification dates or leave the field out.
  • The same meta keywords tag is on every page. Google ignores it, so it can be removed.
  • The homepage meta description is 168 characters and may be cut off in results. Keep it under about 155.

How the redesign applies these fixes

FindingWhat the two concept pages do
1. Empty server HTMLPlain HTML with no JavaScript. All copy, headings and links are in the page source.
2. Description and canonicalBoth are written in the HTML head of each page.
3. Soft 404A dedicated 404.html for the host to serve on missing URLs.
4. Two addressesOne address in the canonical, og:url, structured data and sitemap.
5. Changing titlesOne title per page, 54 and 60 characters, written once in the HTML.
6. AudienceThe teen page is written for teens and students. The company page targets Gen Z marketing searches.
7. HeadingsOne H1, an H2 per section and H3 for items. 33 headings per page with no skipped levels.
8. Structured dataOne JSON-LD graph per page with Organization, FAQPage and either MobileApplication or BreadcrumbList.
9. FAQ answersSix questions per page in native <details>, with answers that match the FAQPage markup word for word.
10. Page speedNo JavaScript, no web fonts and one 11 KB stylesheet. Each page weighs about 28 KiB.
11. Proof on the company pageResults shown at the top with their source and caveat, a four-step process and a six-question FAQ.
